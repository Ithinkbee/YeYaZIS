# «Драгоман» — автоматический машинный перевод

Лабораторная работа № 4, **вариант 4**:

| параметр | значение |
|---|---|
| направление | английский → немецкий |
| методика | перевод с трансфером (системы второго поколения) |
| предметные области | научные статьи по computer science, сочинения по литературе |

Система переводит английский текст на немецкий: разбирает предложение
(части речи, синтаксическое дерево зависимостей), переносит его структуру в
немецкую (порядок слов с глаголом на втором месте и в конце придаточного,
рамочные конструкции, падежи, согласование) и синтезирует немецкие формы.
Выводятся перевод, число слов во входном тексте и число переведённых слов,
частотный список слов с переводом и грамматической информацией (вкладка 1) и
дерево синтаксического разбора выбранного предложения (вкладка 2). Словарь
хранится в базе данных SQLite, его можно править и пополнять — вручную,
правилами словообразования и подсказками словаря Ding. Результаты сохраняются
в TXT в Unicode и печатаются.

Для сравнения есть пословный перевод (системы первого поколения): та же
лексика, но английский порядок слов и без согласования.

А паук Пафнутий, как и в прошлых работах, предлагает поиграть: в **3D-тире**
на Вавилонской башне на него волнами идут английские слова переведённого
текста; попадание паутиной переводит слово на немецкий. Отбив все волны,
игрок получает полностью переведённый документ.

Название — от драгомана, переводчика при посольствах и торговых домах
Востока.

## Быстрый старт

```bash
pip install -r requirements.txt
python run.py
```

Откроется браузер на `http://127.0.0.1:8040/`. Обученные модели анализатора
лежат в `models/` (9 МБ), рабочая база словаря `data/dictionary.sqlite`
создаётся из `data/lexicon/*.tsv` при первом запуске.

```bash
python run.py --no-browser     # только сервер
python run.py --port 8080      # другой порт
```

| переменная | значение |
|---|---|
| `DRAGOMAN_PORT`, `DRAGOMAN_HOST` | адрес интерфейса, по умолчанию `127.0.0.1:8040` |
| `DRAGOMAN_DB` | путь к базе словаря (тесты используют временную) |
| `DRAGOMAN_COMPANION` | `0` — убрать паука Пафнутия вместе с тиром |

Модели можно обучить заново (≈ 30 минут; корпуса UD скачиваются в
`data/treebank/`, 53 МБ):

```bash
python tools/train.py            # лемматизатор, теггер, синтаксический анализатор
python tools/train.py --check    # только проверить модели на тестовых частях корпусов
```

## Как переводит система

Перевод с трансфером по методичке: анализ → лексический и структурный
трансфер → синтез. Готовых библиотек обработки языка (spaCy, NLTK, Stanza) в
работе нет: теггер, лемматизатор, синтаксический анализатор, трансфер и
немецкая морфология написаны с нуля.

1. **Разбиение** (`text/segment.py`). Абзацы, заголовки (`# …`), предложения и
   слова по правилам Penn Treebank: клитики (`don't` → `do` + `n't`,
   `Shakespeare's` → `Shakespeare` + `'s`), сокращения (`e.g.`, `Dr.`), числа,
   проценты, URL, тире и многоточия, слитые со словами.
2. **Части речи** (`english/tagger.py`). Усреднённый перцептрон (жадная
   разметка слева направо, признаки — слово, суффиксы, форма, соседние слова
   и теги) с 49 тегами Penn Treebank (в варианте корпусов UD). Поправки для вопросов с do
   («What does the parser *produce*?») и предложений, где теггер «съел»
   глагол («The system *manages* resources»).
3. **Леммы** (`english/lemmatizer.py`). Правила окончаний по тегу, выученные
   из корпуса, и список неправильных форм (`went` → `go`, `children` → `child`).
4. **Синтаксис** (`english/parser.py`). Анализатор зависимостей arc-hybrid с
   перцептроном и динамическим оракулом; отдельный перцептрон ставит отношения
   Universal Dependencies (`nsubj`, `obj`, `obl`, `acl:relcl`, …). Обучение — на
   тегах, расставленных теггером перекрёстно (5 частей), а не на эталонных.
5. **Исправление разбора** (`translate/transfer.py`). Эвристики для частых
   ошибок: корень-существительное, союз при запятой, композит «training
   samples», разобранный как `nmod`, подлежащее-композит, инфинитив при
   прилагательном, вопросительное слово-дополнение при `does`.
6. **Лексический трансфер** (`translate/lexical.py`, `lexicon/`). Обороты
   (`operating system` → `Betriebssystem`, `depend on` → `abhängen von`)
   склеиваются в одну единицу. Для слова выбирается статья по части речи и
   предметной области (`play` в литературе — `Theaterstück`, иначе — `Spiel`).
   Незнакомое слово переводится правилами словообразования (`optimization` →
   `Optimierung`, `algorithmic` → `algorithmisch`), иначе остаётся как есть и
   попадает в журнал неизвестных слов.
7. **Структурный трансфер.** Для каждого предложения: подлежащее и согласование
   глагола; время, залог, модальность → немецкая глагольная группа (`has been
   tested` → `ist getestet worden`, `need to` → `müssen`); падеж каждой группы
   по роли и предлогу (`of` → Genitiv, `by` при пассиве → `von`); `not a` →
   `kein`, `not X but Y` → `nicht X, sondern Y`; относительные придаточные
   (`which` после предложения → `was`); `to` + инфинитив цели → `um … zu`;
   `it is … that` → `es ist …, dass`; цепочки существительных → сложные слова.
8. **Порядок слов по полям.** Главное предложение — V2: Vorfeld (подлежащее или
   вынесенное обстоятельство), финитный глагол, Mittelfeld, правая скобка
   (причастие, инфинитив, отделяемая приставка). Придаточное — глагол в конце;
   вопрос — глагол первым или после вопросительного слова; длинные
   придаточные — в Nachfeld.
9. **Синтез** (`german/`). Спряжение (≈ 140 сильных и неправильных глаголов,
   отделяемые и неотделяемые приставки, перфект с `haben`/`sein`), склонение
   существительных (слабые, родительный падеж на -s/-es) и прилагательных
   (сильное, слабое, смешанное), артикли и слияния (`in dem` → `im`),
   сложные слова с соединительным -s- (`Sicherheitslücke`), немецкие кавычки
   „…“ и запятые перед придаточными.

Пословный перевод (`translate/direct.py`) делает шаги 1–3 и 6: каждое слово
переводится словарной формой на своём месте.

Схемы: `report/structure.png`, `report/algorithm.png` (блок-схема),
`report/fields.png` (роли → поля немецкого предложения), `report/game_flow.png`
(`python tools/make_diagrams.py`).

## Данные

### Тестовая коллекция — `data/collection/*.txt`, `data/catalog.json`

12 документов, по 6 в каждой предметной области, — разделы статей английской
Википедии (CC BY-SA 4.0), 3000–4400 знаков, 462–682 слова каждый:

| область | документы |
|---|---|
| computer science | Compiler, Operating system, Neural network, Information security, Semantic Web, Machine translation |
| литература | Hamlet, Pride and Prejudice, Frankenstein, Nineteen Eighty-Four, The Great Gatsby, Jane Eyre |

Коллекцию собирает `tools/build_collection.py` (вводный раздел и выбранные
разделы статьи по API Википедии; исходные ответы сохранены в
`data/sources/`, поэтому `--offline` собирает коллекцию без сети).

### Эталонные переводы — `data/reference/references.tsv`

По 10 предложений из каждого документа (120) с немецким переводом,
подготовленным независимо от системы, близко к тексту. С ними сравнивается
машинный перевод.

### Словарь — `data/lexicon/*.tsv` → `data/dictionary.sqlite`

≈ 5000 статей: служебные слова, существительные (род, мн. ч., слабое
склонение), глаголы (отделяемые приставки `vor|stellen`, возвратность,
управление `prep=auf+A`, Dativ-дополнение, перфект с `sein`), прилагательные,
наречия, 394 оборота, имена собственные с немецким соответствием
(`Denmark` → `Dänemark`). У слова может быть несколько статей — для областей
CS, литературы и общая. Файл `08-general.tsv` — частые слова корпусов UD, которых
не хватало на незнакомых текстах.

Правки пользователя хранятся в базе отдельно от исходных таблиц и переживают
их обновление. Неизвестные слова попадают в журнал; на странице пополнения для
них предлагаются догадки по правилам словообразования и статьи словаря Ding
(TU Chemnitz, GPL; скачивается кнопкой в `data/external/`).

### Модели — `models/`, корпуса — `data/treebank/`

Universal Dependencies English: EWT и GUM (теги Penn Treebank — для всех
моделей), LinES и ParTUT (только для синтаксического анализатора). Обучение —
29 096 предложений, 509 тыс. слов.

## Интерфейс

| страница | что показывает |
|---|---|
| `/` | ввод текста или файла (TXT, MD, HTML, DOCX, PDF), область, способ перевода; документы коллекции |
| `/t/<id>` | перевод (параллельно с оригиналом), статистика; вкладки: **1** — частотный список слов с переводом и грамматикой, **2** — дерево разбора выбранного предложения (зависимости и составляющие), **3** — другой способ перевода, пополнение словаря |

| `/collection`, `/doc/<id>` | коллекция и перевод документа |

| `/shooter` | тир Пафнутия; план волн — `/api/shooter/plan` |

## Результаты

`python tools/evaluate.py` — все числа в `report/evaluation.json`, графики
`report/eval_*.png`.

### Качество перевода (120 эталонных предложений)

| | BLEU-4, трансфер | BLEU-4, пословно | chrF, трансфер | chrF, пословно |
|---|---|---|---|---|
| computer science | **40,7** | 13,6 | **73,9** | 61,1 |
| литература | **31,0** | 16,9 | **66,8** | 56,5 |
| вся коллекция | **35,6** | 15,4 | **70,3** | 58,8 |

Перевод с трансфером лучше пословного в 110 предложениях из 120 (по chrF),
хуже — в 9. Точность n-грамм (трансфер / пословно): униграммы 69,8 / 56,4 %,
биграммы 42,1 / 20,4 %, 4-граммы 19,4 / 5,4 % — порядок слов и формы дают
главный выигрыш на длинных n-граммах.

### Доля переведённых слов

| | с правилами словообразования | только словарь |
|---|---|---|
| коллекция (6721 слово) | 99,3 % | 99,2 % |
| незнакомые тексты: 10 документов тестовой части GUM (8357 слов) | **92,1 %** | 89,1 % |

На коллекции словарь находит почти всё — он составлялся под неё. На
незнакомых текстах (академические статьи, эссе, учебники, биографии,
рассказы) правила словообразования дают +3 п. п.

### Анализатор (тестовые части корпусов UD)

| корпус | теги | леммы | UAS | LAS |
|---|---|---|---|---|
| EWT (веб-тексты) | 94,1 % | 96,8 % | 84,7 % | 80,1 % |
| GUM (разные жанры) | 96,0 % | 98,5 % | 84,5 % | 80,3 % |
| LinES (литература) | — | — | 84,3 % | 78,6 % |
| ParTUT (право, Википедия) | — | — | 86,4 % | 81,2 % |

### Время на документ (≈ 560 слов)

| этап | мс |
|---|---|
| разбиение на предложения и слова | ≈ 6 |
| теги и леммы | ≈ 29 |
| синтаксический анализ | ≈ 90 |
| трансфер и синтез | ≈ 32 |
| всего (со списком слов и статистикой) | ≈ 172 |

### Выводы

1. Трансфер окупается: BLEU выше в 2,3 раза, chrF — на 11 пунктов; разница
   растёт с длиной n-граммы, то есть дело в порядке слов и формах, а не в
   выборе слов (словарь у способов общий).
2. Научные тексты переводятся лучше литературных (BLEU 40,7 против 31,0):
   терминология однозначна, предложения построены по немногим схемам. В
   текстах о романах — цитаты, имена, обороты разговорной и книжной речи,
   длинные предложения с вставками.
3. Главный источник ошибок — анализ: неверный тег (глагол, принятый за
   существительное, и наоборот) и синтаксис (UAS ≈ 85 %: в предложении из 30
   слов в среднем 4–5 неверных связей). Ошибочное прикрепление предложной
   группы или союза переставляет целые группы; поправки теггера и эвристики
   исправления разбора закрывают самые частые случаи.
4. Пословный перевод иногда выигрывает (9 предложений) — когда трансфер
   ошибается в структуре, а пословная замена сохраняет хотя бы порядок
   английского оригинала, близкий к немецкому.

## Тир Пафнутия (дополнительный функционал)

Трёхмерная игра (three.js r160, без сборки — ES-модуль в `static/vendor/`).
Пафнутий стоит на вершине Вавилонской башни; через шесть ворот парапета на него
волнами идут английские слова переведённого текста.

* **Каждое разное слово текста — один противник**, и выходит он ровно один раз.
  У слова — его немецкий перевод из перевода текста (если слово в переводе
  слилось с соседями в сложное слово — словарный); имена не переводятся.
* **Противники разные**: мелочь — служебные слова ≤ 4 букв (маленькие,
  быстрые, бегут стайками); слова — существительные, прилагательные, наречия,
  имена (идут и кусают); **слова с пушками** — глаголы (держат дистанцию и
  стреляют буквами).
* **Мини-босс в конце каждой волны** — одно из самых длинных слов документа: при
  N волнах первую закрывает N-е по длине слово, вторую — (N−1)-е, …, последнюю —
  самое длинное. С каждым попаданием над боссом проступает немецкий перевод.
* **Число волн (1–10) задаётся перед игрой**, волны растут как 1 : 2 : … : N, и за
  все волны выходят все слова текста. Внутри волн слова идут от коротких к
  длинным.
* Попадание паутиной переводит слово; в панели текста (Tab) оно меняется на
  немецкое. Над противником перевод показан в словарной форме: существительное —
  в именительном падеже того же числа (contradictions → Widersprüche),
  прилагательное — без окончания (greatest → am größten). **Победа — полностью
  переведённый документ** с кнопками «Сохранить перевод (TXT)» и «Открыть
  перевод».

Управление: W/↑ — вперёд, S/↓ — назад, A/← и D/→ — влево и вправо (паук
поворачивается и бежит в ту сторону), мышь — поворот камеры, левая кнопка —
выстрел, правая (или E) —
ловчая сеть (переводит всех рядом), Пробел — прыжок, Shift — рывок, F — полный
экран, Esc — пауза. Три уровня сложности, мухи лечат паука.

План волн строит сервер (`dragoman/game.py`, проверяется тестами на Python),
правила боя — `static/shooter_rules.js` (без DOM и three.js, проверяются
`tests/shooter_rules.test.js` в node или, без node, в движке V8 браузера —
`tools/run_js_tests.py`), отрисовка — `static/shooter.js`.
`?debug=1` открывает `window.ShooterDebug` (выпустить слова, пропустить волну,
победить) — так снимаются кадры для отчёта.

`DRAGOMAN_COMPANION=0` убирает паука вместе с тиром; на перевод паук не
влияет (проверяется тестом в отдельном процессе).

### Структуры данных

| структура | назначение |
|---|---|
| `Layout`, `Paragraph`, `Sentence`, `Token` | текст: абзацы, заголовки, предложения, слова со смещениями |
| `Word`, `AnalyzedSentence`, `AnalyzedDocument` | слово с леммой, тегом, вершиной и отношением; дерево предложения |
| `Entry` | словарная статья: перевод, род, мн. ч., управление, область, источник |
| `Choice` | выбранный перевод слова и как он найден (словарь, правило, имя, число, нет) |
| `Agr`, `Part`, `VerbGroup`, `EnglishVerb` | согласование; составляющая немецкого предложения с полем; немецкая и английская глагольные группы |
| `G`, `Sentence` (output) | немецкое слово со ссылкой на исходные слова; переведённое предложение и пояснения трансфера |
| `ListItem`, `Translation` | строка частотного списка; результат перевода со статистикой |
| `Enemy`, `Wave`, `Plan` | слова-противники, волны, план тира |

## Сценарии и тесты

```bash
python tools/build_collection.py --offline   # коллекция из сохранённых ответов
python tools/train.py                        # обучение моделей (--check — проверка)
python tools/evaluate.py                     # оценка и графики
python tools/make_diagrams.py                # схемы
python tools/screenshots.py                  # снимки экрана (система должна работать)
python tools/make_report.py                  # отчёт в DOCX
python tools/run_js_tests.py                 # правила тира: node, а без него Edge/Chrome
python -m pytest tests -q                    # тесты
```

Тесты проверяют разбиение на слова и предложения, немецкую морфологию
(спряжение, причастия, склонение, сложные слова), анализатор (теги, леммы,
дерево — всегда дерево), словарь (поиск по области, правки переживают
обновление таблиц, журнал неизвестных слов, импорт и экспорт, правила
словообразования), **55 предложений с трансфером — каждое на своё правило**
(V2, рамка, пассив, kein, um … zu, модальные обороты, вопросы, придаточные,
sondern, исправления разбора…), статистику и частотный список, сохранение в
UTF-16 с меткой и
CR LF, BLEU и chrF на посчитанных вручную примерах, выравнивание эталонов с
коллекцией, веб-интерфейс, выключатель паука и план тира (каждое слово ровно
один раз, волны растут, боссы — самые длинные слова в нужном порядке, надписи
в словарной форме). Правила боя проверяет `tests/shooter_rules.test.js`
(51 проверка) — в node, а если node не установлен, в движке V8 браузера Edge
или Chrome без окна. Всего 205 тестов.

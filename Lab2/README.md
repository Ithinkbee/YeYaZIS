# «Толмач» — автоматическое распознавание языка текста

Лабораторная работа № 2, **вариант 4**:

| параметр | значение |
|---|---|
| языки | русский, немецкий |
| формат документов | HTML |
| методы | N-грамм, алфавитный, нейросетевой |

Система определяет, на каком языке написан HTML-документ. Каждый документ
разбирается тремя методами сразу, и по всей тестовой коллекции считается
точность и быстродействие каждого из них.

---

## Быстрый старт

```bash
pip install -r requirements.txt
python run.py
```

Откроется браузер на `http://127.0.0.1:8010/`. Профили языков при первом
запуске строятся автоматически (около 4 секунд) и сохраняются в `models/`;
дальше читаются оттуда.

Если браузер не нужен:

```bash
python run.py --no-browser          # только сервер
python run.py --port 8080           # другой порт
python run.py --retrain             # построить профили заново
```

---

## Что делает система

Работа идёт в три шага, как описано в методичке.

**Шаг 1. Предварительная обработка.** Из HTML извлекается видимый текст:
удаляются теги, содержимое `<script>` и `<style>`, раскрываются HTML-сущности.
Затем текст приводится к строчным буквам, а всё, что не является буквой, —
к пробелу. Немецкие `ä ö ü ß` сохраняются: без них немецкий профиль теряет
заметную часть своих признаков. Составные символы приводятся к форме NFC,
иначе «ü» одним знаком и «u + диерезис» дали бы разные N-граммы.

**Шаг 2. Сравнение профилей.** Для каждого языка по обучающему корпусу
заранее построен поисковый образ языка (ПОЯ). По тем же правилам строится
образ входного документа (ПОД), после чего метод считает расстояние.

**Шаг 3. Выбор языка.** Побеждает язык с наименьшим расстоянием. Итоговый
ответ системы — голосование трёх методов; при равенстве голосов побеждает
метод с наибольшим отрывом ближайшего языка от второго.

Схемы в графическом виде: `report/algorithm.png`, `report/structure.png`,
`report/profiles.png` (строятся командой `python tools/make_diagrams.py`).

## Методы

Все три метода имеют общий интерфейс (`tolmach/methods/base.py`) и
различаются только правилом построения образа и метрикой сравнения.
Метрика у всех приведена к отрезку `[0, 1]`, иначе методы были бы
несопоставимы между собой.

### Метод N-грамм (Кавнар — Тренкл, 1994)

Слово обрамляется заполнителем (`_слово_`), из полученной строки извлекаются
все подстроки длиной 1–5. N-граммы сортируются по убыванию частоты, первые
300 образуют профиль, номер в списке — ранг N-граммы.

Расстояние — мера несовпадения позиций (out-of-place): для каждой N-граммы
документа берётся `|ранг_в_документе − ранг_в_языке|`, а отсутствующей в
профиле языка N-грамме назначается максимальный штраф, равный размеру
профиля. Сумма делится на `размер профиля × штраф`.

### Алфавитный метод

Язык описывается вектором относительных частот букв своего алфавита.
Расстояние — манхэттенское: сумма модулей разностей частот по объединению
алфавитов, делённая на 2. Буква, которой в языке нет, отдаёт в сумму всю
свою частоту, поэтому для языков с разными системами письма расстояние сразу
близко к максимуму.

### Нейросетевой метод

Документ описывается вектором частот 400 символьных N-грамм длиной 1–3.
Словарь признаков отбирается «по кругу» — поровну от каждого языка, иначе
более объёмный корпус вытеснил бы признаки второго языка.

Вектор подаётся на персептрон с одним скрытым слоем (32 нейрона, `tanh`) и
`softmax` на выходе. Сеть написана на numpy без внешних фреймворков:
обратное распространение ошибки и оптимизатор Adam занимают один метод, что
удобно для разбора. Расстоянием считается `1 − P(язык)` — чтобы «побеждает
наименьшее расстояние» работало одинаково во всех трёх методах.

Обучение идёт на фрагментах **нескольких длин сразу** (150, 300 и 600
символов). Это не украшение: при обучении только на длинных фрагментах
вектор частот короткого документа оказывается для сети непривычно разрежен,
и точность на коротком входе проседает.

## Данные

### Обучающий корпус — `data/train/<язык>/*.txt`

Методичка требует от 20 до 120 Кб на язык. Фактически:

| язык | файлов | объём | букв | слов |
|---|---|---|---|---|
| русский | 46 | 78.6 Кб | 36 716 | 5 709 |
| немецкий | 6 | 41.1 Кб | 34 620 | 5 764 |

Объём в байтах различается вдвое, потому что кириллица в UTF-8 занимает два
байта на букву, а латиница — один. Сравнивать корпуса следует по числу букв
и слов, и по ним они практически равны (перекос 1.06×). Это существенно:
корпус большего объёма дал бы более подробный профиль и незаслуженное
преимущество своему языку.

**Происхождение текстов.** Русская часть (`lab1-*.txt`) собрана из коллекции
документов лабораторной работы № 1 — её повторное использование разрешено.
Каталог `Lab1` открывается **только на чтение**: сценарий сборки ничего в нём
не создаёт, не меняет и не удаляет. К ней добавлены три текста общей
тематики (`own-*.txt`), чтобы русский корпус не состоял из одних только
технических текстов, тогда как немецкий — из текстов общего характера.
Немецкая часть набрана специально для работы: шесть текстов по истории,
природе, науке, быту, технике и культуре.

Пересобрать русскую часть:

```bash
python tools/build_corpus.py            # собрать
python tools/build_corpus.py --dry-run  # посмотреть, что будет взято
python tools/build_corpus.py --clean    # убрать прежний импорт и собрать заново
```

### Тестовая коллекция — `data/collection/*.html`

20 HTML-документов: 10 русских и 10 немецких, примерно по странице A4 каждый
(2155–2891 букв, среднее 2534, разброс 205). Эталонная разметка —
`data/labels.csv`.

Две особенности коллекции сделаны намеренно:

- **Темы попарно совпадают** между языками: маяки и `Leuchttürme`, пчёлы и
  `Imkerei`, хлеб и `Brot`, карты и `Kartografie` и так далее. Если бы
  русские документы были о природе, а немецкие о технике, методы могли бы
  разделять их по теме, а не по языку, и оценка оказалась бы завышенной.
- **Разметка неоднородна**: у документов разные шаблоны, в них есть
  `<style>` и `<script>` с латиницей, меню и подвалы. Это проверяет шаг 1:
  если бы содержимое `<style>` просочилось в текст, профиль русского
  документа был бы испорчен латиницей. Два русских документа вдобавок
  содержат настоящие латинские вкрапления (почтовые коды, термины монтажа) —
  1–2 % букв.

Темы тестовой коллекции не встречаются в обучающем корпусе: иначе
проверялось бы запоминание, а не обобщение.

## Интерфейс

| страница | что показывает |
|---|---|
| `/` | тестовая коллекция, результат по каждому документу, сводная статистика |
| `/document/<файл>` | разбор одного документа: решение каждого метода и чем оно обосновано |
| `/raw/<файл>` | исходный HTML-документ (активная ссылка из таблицы) |
| `/compare` | точность, быстродействие, матрицы ошибок и два опыта |
| `/profiles` | поисковые образы языков, алфавиты, сведения об обучении сети |
| `/check` | распознавание своего текста или загруженного файла |
| `/chess` | партия с Пафнутием (см. «Пафнутий и шахматы») |
| `/help` | справка: работа с программой, разбор методов, устранение неполадок |
| `/print` | версия отчёта для печати |

**Сохранение в файл** — `/export/csv`, `/export/json`, `/export/txt`:

- **CSV** — таблица «документ × метод» с расстояниями и временем, плюс сводка;
- **JSON** — полные данные прогона, включая матрицы ошибок и опыты;
- **TXT** — готовый к печати текстовый протокол.

**Печать** — страница `/print` либо печать любой страницы: правила
`@media print` убирают навигацию, кнопки и формы и запрещают разрывать
таблицы посередине строки.

## Результаты

### Точность и быстродействие на полных документах

| метод | точность | мс на документ | док./с |
|---|---|---|---|
| Алфавитный | 100 % (20/20) | 0.43 | ≈ 2300 |
| Нейросетевой | 100 % (20/20) | 4.72 | ≈ 210 |
| N-грамм | 100 % (20/20) | 8.75 | ≈ 115 |
| Согласованное решение | 100 % (20/20) | 13.91 | ≈ 70 |

Все три метода безошибочны, и разногласий между ними нет ни по одному
документу. Это не достоинство реализации, а свойство пары языков: кириллица
и латиница не пересекаются, и задача решается на уровне алфавита. Время
согласованного решения — сумма времени всех методов: чтобы провести
голосование, нужно выполнить каждый.

### Зависимость от длины входа

Каждый документ нарезан на окна по границам слов; на каждой длине испытано
48–100 фрагментов.

| метод | 10 симв. | 20 | 40 | 80 | 150 | 300 | 600 | 1200 |
|---|---|---|---|---|---|---|---|---|
| N-грамм | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % |
| Алфавитный | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % |
| Нейросетевой | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % |

Для этой пары языков хватает одного-двух слов. Опыт всё же нужен: именно он
обнаружил, что нейросетевой метод, обученный на фрагментах одной длины,
проседал до 90 % на коротком входе, — отсюда обучение на нескольких
масштабах.

### Поведение на смешанном тексте

Русский документ постепенно замещается немецким; в таблице — доля смесей,
отнесённых к немецкому.

| метод | 40 % | 45 % | 47.5 % | 50 % | 52.5 % | 55 % | перелом |
|---|---|---|---|---|---|---|---|
| N-грамм | 0 | 60 | 90 | 100 | 100 | 100 | **45.0 %** |
| Алфавитный | 0 | 0 | 0 | 20 | 100 | 100 | **52.5 %** |
| Нейросетевой | 0 | 0 | 0 | 50 | 100 | 100 | **50.0 %** |

Здесь методы наконец расходятся. Метод N-грамм склоняется к немецкому
раньше середины: немецкие слова длиннее, и с той же длины текста их приходит
в профиль больше. Алфавитный метод, наоборот, дольше держится за русский.
Нейросетевой делит равную смесь ровно пополам — обучение выровняло его
границу, тогда как у двух других она задана видом метрики и смещена
свойствами самих языков.

### Выводы

1. Для языков с **разными системами письма** достаточно алфавитного метода:
   он точен так же, как остальные, и при этом в 20 раз быстрее метода
   N-грамм. Платить за более сложные методы здесь не за что.
2. Ценность методов N-грамм и нейросетевого раскрывается на парах с **общим
   алфавитом** (немецкий — французский, испанский — итальянский), где
   решение приходится принимать по оттенкам частот, а не по набору букв.
   Алфавитный метод там опустился бы почти до уровня угадывания.
3. Голосование трёх методов не улучшило точность — улучшать было нечего, —
   но стоит суммы их времён. Оно оправдано там, где методы ошибаются
   по-разному, а не там, где все они безошибочны.
4. Нейросетевой метод требует обучения (≈ 4 с) и хранения весов (243 Кб),
   тогда как два других строят профиль за доли секунды. Зато его граница
   решения не задана вручную, а выведена из данных — это и есть его главное
   отличие от первых двух.

## Пафнутий и шахматы

Паук из первой лабораторной работы перебрался во вторую. Там он сидел в углу
и комментировал поисковую выдачу; здесь у него появилось занятие.

### Что он делает

**Сидит в углу.** На каждой странице, кроме версии для печати. Реплики
подобраны по разделу, а не случайно из общего мешка.

**Сторожит форму «Свой текст».** Прежде чем текст уйдёт на распознавание,
нужно поставить мат чёрному королю в два хода. Засчитывается первый ход,
после которого мат неизбежен при любом ответе чёрных.

**Играет партию** на странице `/chess` — обычные шахматы со всеми правилами,
вы за белых.

### Правило взятия

Это и есть суть затеи. Чтобы взять фигуру паука, нужно определить язык слова,
записанного латиницей:

| ответ | что происходит |
|---|---|
| верно | взятие состоится, фигура ваша |
| неверно | Пафнутий съедает фигуру, которой вы ходили, и забирает ход |

Слова берутся из настоящего обучающего корпуса. Русские транслитерируются
(`работа` → `rabota`), у немецких сворачиваются умлауты (`Wärme` → `waerme`).
Оба языка оказываются в одном алфавите, и узнать язык можно только по
строению слова — ровно той задачей заняты методы системы.

Два случая оговорены отдельно, чтобы на доске не возникло невозможной
позиции: короля паук не снимает, и не снимает фигуру, прикрывающую короля.
В обоих случаях игрок теряет только ход.

### Неожиданный побочный результат

После ответа показывается, что сказали бы сами методы. Как правило, они
ошибаются:

```
слово: chisla   (в корпусе «числа»)
ваш ответ:      русский   — верно
методы системы: ngram → de, alphabet → de, neural → de
```

Профили русского языка построены по кириллице, поэтому латинская запись для
всех трёх методов выглядит немецкой. Это наглядная граница алфавитного
подхода и случай, когда человек оказывается точнее системы. Проверяется
тестом `test_system_fails_on_transliterated_russian`.

### Про задачи

Задач восемь. Они не сочинены вручную, а найдены перебором
(`tools/find_puzzles.py`) и отобраны по трём условиям: мат в два хода
существует, мата в один нет, первый ход единственный. Каждое условие
проверяется тестами полным перебором, поэтому ошибиться в разметке
невозможно. После трёх неудачных попыток Пафнутий называет фигуру, которой
надо ходить; кнопка «Другая задача» меняет позицию.

Правила шахмат реализованы на Python, а не в браузере, — иначе задачи
пришлось бы проверять дважды, и две проверки рано или поздно разошлись бы.
Корректность генератора ходов подтверждена **perft**: подсчётом числа ходов
на несколько полуходов вперёд из пяти общеизвестных позиций, включая
рокировку через битое поле, взятие на проходе, превращения и связки.
Состояния партии на сервере нет: браузер присылает позицию в FEN, сервер
возвращает новую.

### Как выключить

Вся надстройка подчинена одной переменной окружения:

```bash
TOLMACH_COMPANION=0 python run.py     # чистая лабораторная работа
```

Исчезают паук, задача на форме, страница партии и викторина; `/chess`
отвечает 404, игровое API — 403. На распознавание языка и на метрики
надстройка не влияет ни в каком виде: это проверяется отдельным набором
тестов (`tests/test_companion_off.py`), который поднимает приложение в
отдельном процессе с выключенной надстройкой.

**Оговорка про строгую калитку.** По вашему выбору задача обязательна: без
решения текст на распознавание не уходит. Это заметно замедляет работу с
формой «Свой текст», если ей пользоваться часто. Смягчено тем, что задача
всегда проходима (подсказка и смена позиции), что гейт стоит только на этой
форме — коллекция, сравнение методов и профили открыты всегда, — и что есть
выключатель выше. Калитка живёт в браузере: прямой POST на `/check`
(как в тестах) её не проходит.

Шахматы и викторина не связаны с распознаванием языка ни в одну сторону:
подпакет `chess` ничего не знает о языках, а `methods` — о доске. Их
соединяет единственное место — `web/game.py`, где взятие фигуры превращается
в вопрос викторины.

### Структуры данных

| структура | назначение |
|---|---|
| `Document` | входной документ после шага 1: текст, число букв и слов, эталонный язык |
| `Profile` | поисковый образ: признак → ранг и признак → частота; одна структура и для ПОЯ, и для ПОД |
| `MethodResult` | решение одного метода: расстояния до языков, выбранный язык, время, уверенность |
| `Verdict` | сводное решение по документу: результаты всех методов, итоговый язык, согласие |
| `MethodScore` | качество метода: точность, матрица ошибок, точность и полнота по языкам, время |
| `Report` | результат прогона всей коллекции |

## Использованные компоненты

| компонент | роль | обязателен |
|---|---|---|
| **FastAPI** + **uvicorn** | веб-сервер и маршрутизация | да |
| **Jinja2** | шаблоны страниц | да |
| **python-multipart** | загрузка файла в форме «Свой текст» | да |
| **numpy** | матричные операции в нейросетевом методе | да |
| **BeautifulSoup4** | разбор HTML | нет — есть запасной разборщик на `html.parser` |
| **matplotlib** | графики и схемы для отчёта | нет — нужен только сценариям в `tools/` |
| **pydantic** | проверка тела запросов игрового API (идёт с FastAPI) | да |
| **pytest**, **httpx** | тесты | нет |

Готовых библиотек распознавания языка (`langdetect`, `langid`, `fasttext`)
в работе **нет**: все три метода, включая нейронную сеть с обратным
распространением ошибки, реализованы с нуля. Из внешних компонентов в
расчётах участвует только numpy — как библиотека линейной алгебры.

Шахматный движок тоже написан с нуля: ни `python-chess`, ни готовых
библиотек для браузера. Фигуры рисуются символами Unicode, поэтому картинок
и шрифтов не требуется.

## Замечания о реализации

**Обучение воспроизводимо.** Зерно генератора случайных чисел задано
(`config.RANDOM_SEED`), а признаки при равных частотах упорядочиваются по
самому признаку. Без второго условия профиль зависел бы от порядка обхода
словаря и результаты перестали бы повторяться.

**Контрольная выборка отделяется до нарезки.** Корпус делится на обучающую и
контрольную части по тексту, и только потом режется на фрагменты. Если
разделять после нарезки, перекрывающиеся фрагменты попали бы в обе выборки
и контрольная точность оказалась бы завышенной.

**Кэш прямого прохода сети хранит сам профиль, а не его `id`.** Первая
версия кэшировала вероятности по `id(profile)`; адреса освобождённых
объектов переиспользуются, и метод начинал возвращать ответ, посчитанный для
предыдущего документа. В опыте это выглядело как ровно 50 % точности на
одной длине фрагмента. Проверки
`test_alternating_documents_do_not_leak` закрывают этот случай.

**Обход каталога коллекции защищён.** Имя файла в `/raw/<имя>` проверяется на
выход за пределы `data/collection`.

**Кэш нейросети сгорел на переиспользовании адресов.** Первая версия
кэшировала вероятности по `id(profile)`; адреса освобождённых объектов
переиспользуются, и метод начинал возвращать ответ, посчитанный для
предыдущего документа. В опыте это выглядело как ровно 50 % точности на одной
длине фрагмента. Теперь в кэше лежит сам профиль; случай закрыт тестом
`test_alternating_documents_do_not_leak`.

**Ни решение задачи, ни ответ викторины не уходят в браузер.** Задача
отдаётся одной позицией и списком законных ходов; правильность первого хода
проверяется на сервере перебором. Слово викторины приходит без языка, ответ
сверяется там же. Иначе и то и другое читалось бы в исходном коде страницы.

**Падежи имени заданы целиком.** Склейка `{{ companion_name }}ем` в шаблоне
давала «Партия с Пафнутийем»; правильная форма «Пафнутием» получается не
приписыванием окончания, поэтому формы перечислены в `pafnuty.py` и
проверяются тестом.

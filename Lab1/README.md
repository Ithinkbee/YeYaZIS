# ИПС «Арахна»

Информационно-поисковая система по документам локальной вычислительной сети.
Лабораторная работа «Разработка информационно-поисковой системы. Реализация
методов оценки качества её работы», **вариант 3**:

| Параметр варианта | Значение | Где реализовано |
|---|---|---|
| Реализация элементов ИИ | интерфейс с пользователем | [`arachne/ai/`](arachne/ai/), веб-интерфейс |
| Сфера применения | локальная вычислительная сеть | [`arachne/crawler.py`](arachne/crawler.py) |
| Стратегия поиска | векторная (TF-IDF + косинусная мера) | [`arachne/indexer.py`](arachne/indexer.py), [`arachne/search.py`](arachne/search.py) |
| Язык | русский | [`arachne/text/morphology.py`](arachne/text/morphology.py) |

## Быстрый старт

```bash
pip install -r requirements.txt
python tools/make_collection.py     # создать тестовую коллекцию (108 документов)
python tools/reindex.py --add-nodes --load-qrels   # обойти, проиндексировать, загрузить эталон
python run.py                       # запустить систему, откроется браузер
```

Далее в интерфейсе: **Индекс → «Добавить тестовые узлы ЛВС» → «Запустить обход
и индексацию»**, после чего можно искать. Свои ресурсы добавляются там же:
обычный каталог (`D:\Отдел`) или сетевая папка (`\\сервер\обмен`).

## Из чего состоит система

Три компонента, как того требует методичка:

```
      ┌──────────────┐      ┌──────────────┐      ┌─────────────────┐
      │  Агент/паук  │ ───▶ │ База данных  │ ◀─── │ Поисковый       │
      │ crawler.py   │      │ SQLite, db.py│      │ механизм        │
      │ обход ЛВС    │      │ индекс, qrels│      │ search.py + web │
      └──────────────┘      └──────────────┘      └─────────────────┘
```

| Модуль | Назначение |
|---|---|
| [`arachne/crawler.py`](arachne/crawler.py) | обход каталогов и UNC-ресурсов, инкрементальность по mtime и sha1 |
| [`arachne/text/extract.py`](arachne/text/extract.py) | извлечение текста из txt, md, csv, html, docx, pdf, rtf |
| [`arachne/text/morphology.py`](arachne/text/morphology.py) | токенизация, стоп-слова, лемматизация (pymorphy3) |
| [`arachne/indexer.py`](arachne/indexer.py) | инвертированный индекс, формулы (1.5) и (1.6), нормы векторов |
| [`arachne/search.py`](arachne/search.py) | поисковый образ запроса, косинусная мера, ранжирование |
| [`arachne/ai/suggest.py`](arachne/ai/suggest.py) | разбор ЕЯ-запроса, автодополнение, опечатки, синонимы |
| [`arachne/ai/feedback.py`](arachne/ai/feedback.py) | обратная связь по релевантности (Рокчио), похожие документы |
| [`arachne/ai/llm.py`](arachne/ai/llm.py) | необязательный языковой помощник (любой OpenAI-совместимый сервис) |
| [`arachne/evaluation/`](arachne/evaluation/) | метрики РОМИП, эталонная разметка, графики |
| [`arachne/web/`](arachne/web/) | веб-интерфейс (FastAPI + Jinja2) |
| [`arachne/companion.py`](arachne/companion.py) | паук-компаньон и достижения (отключаемо) |

## Модель поиска

Вес термина в документе — по формулам методички:

```
B_i  = log( N / P_i )          инверсная частота термина            (1.5)
A_ij = Q_ij · B_i              вес термина i в документе j          (1.6)
```

Вектор запроса: `w_qj = 1`, если слово есть в запросе, иначе 0 (термины,
добавленные системой — синонимы, исправления опечаток — входят с весом 0,5).
Релевантность — косинус угла между векторами:

```
sim(D, Q) = (D, Q) / ( ‖D‖ · ‖Q‖ )
```

## Элементы ИИ в интерфейсе (ядро варианта 3)

* морфологический разбор запроса с показом, «как система поняла запрос»;
* автодополнение по словарю индекса и по истории запросов;
* исправление опечаток (расстояние Дамерау — Левенштейна) — «возможно, вы имели в виду»;
* расширение запроса синонимами из тезауруса `data/synonyms_ru.json`;
* обратная связь по релевантности: «больше таких» / «не то» (метод Рокчио);
* похожие документы по косинусной мере документ-документ;
* объяснение выдачи: вклад каждого термина в итоговый ранг;
* подсказки при пустой выдаче;
* необязательный языковой помощник поверх найденного (Groq, OpenRouter, Mistral — на выбор).

## Оценка качества

Раздел «Оценка качества» считает метрики, принятые в РОМИП: точность, полнота,
F-мера, P@n, R-точность, AP и MAP, 11-точечный график «точность — полнота»,
DCG/nDCG, bpref. Результаты выводятся таблицами и графиками, выгружаются в CSV
и PNG (`report/`).

Из командной строки:

```bash
python tools/run_eval.py --load-qrels     # загрузить эталон и посчитать метрики
python tools/run_eval.py --compare --plots  # сравнение конфигураций + графики PNG
```

Эталон: 36 информационных потребностей, 271 оценка релевантности
(`data/eval_queries.csv`, `data/qrels.csv`). Разметку можно править в интерфейсе
(раздел «Разметка») и сохранять обратно в CSV.

Коллекция: 108 документов на трёх узлах ЛВС (NODE-A, NODE-B, NODE-C) в пяти
форматах (txt, md, html, docx, pdf), десять тем. Темы намеренно пересекаются по
лексике: «сеть» встречается в ЛВС, в нейронных сетях и в железнодорожной сети,
«маршрут», «узел» и «пакет» — в ЛВС и в транспорте, «индекс» — в СУБД и в
поиске. Без такой омонимии метрики качества вырождаются: любой запрос
отделяет релевантное от нерелевантного тривиально.

## Языковой помощник (необязательно)

Слой работает с любым сервисом, у которого OpenAI-совместимый API — провайдер
задаётся в `.env`:

```ini
LLM_PROVIDER=groq          # groq | openrouter | mistral | cerebras | together
LLM_API_KEY=ваш_ключ
# LLM_BASE_URL=...         # если нужен адрес, отличный от заготовки
# LLM_MODEL=...            # если нужна другая модель
```

Проверить, что доступно с вашего адреса:

```bash
python tools/check_llm.py --scan
```

Утилита показывает внешний IP, отвечает ли эндпоинт и принимает ли он ключ.

Важно: доступность сервиса определяется адресом выхода в сеть, а не ключом.
Groq, Cerebras и Together закрывают доступ с адресов дата-центров — а к ним
относится почти любой коммерческий VPN, — и отвечают `403` ещё до проверки
ключа. Перебор узлов одного и того же VPN тут не помогает: весь пул адресов
провайдера попадает в списки целиком. Поэтому `403` лечится не VPN, а сменой
провайдера: OpenRouter и Mistral таких ограничений не ставят и работают в том
числе с адресов дата-центров.

```ini
LLM_PROVIDER=openrouter
LLM_API_KEY=ключ_с_openrouter.ai/keys
```

Модель по умолчанию для OpenRouter — бесплатная (`…:free`), карта не нужна.
Обратно к Groq стоит возвращаться только с обычного домашнего или мобильного
подключения без VPN.

**Помощник выключен по умолчанию** и в сеть не обращается: система не должна
зависеть от доступности стороннего сервиса. Поиск, ранжирование и оценка
качества языковую модель не используют — это необязательная надстройка над
готовой выдачей. Чтобы включить, нужны и ключ, и явный флаг:

```ini
ARACHNE_LLM=1
LLM_PROVIDER=openrouter
LLM_API_KEY=ваш_ключ
```

## Тесты

```bash
python -m pytest tests -q
```

35 тестов: извлечение текста и кодировки, лемматизация, формулы (1.5)/(1.6),
косинусная мера, инкрементальность обхода, исправление опечаток, Рокчио и все
метрики качества на примерах с известным ответом.

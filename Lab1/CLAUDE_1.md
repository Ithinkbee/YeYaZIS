# ИПС «Арахна» — правки и нововведения

Файл для Claude Code. Содержит правила работы по проекту, четыре исправления и
спецификацию геймификации. Порядок работы — по разделу «Этапы» в конце.

---

## 0. Контекст проекта

Лабораторная работа «Разработка информационно-поисковой системы», **вариант 3**:
элементы ИИ в интерфейсе, сфера — ЛВС, стратегия — векторная (TF-IDF + косинус),
язык — русский. Стек: Python 3.14, FastAPI + Jinja2, SQLite, pymorphy3, без
фронтенд-сборки (ванильный JS в `arachne/web/static/app.js`).

| Что | Где |
|---|---|
| Поисковый механизм, ПОЗ, косинус | `arachne/search.py` |
| Инвертированный индекс, формулы (1.5)/(1.6) | `arachne/indexer.py` |
| Обход ЛВС | `arachne/crawler.py` |
| Морфология, стоп-слова, синонимы | `arachne/text/`, `data/stopwords_ru.txt`, `data/synonyms_ru.json` |
| ИИ-надстройки интерфейса | `arachne/ai/` (suggest, feedback, llm) |
| Метрики РОМИП, эталон | `arachne/evaluation/` |
| Веб | `arachne/web/app.py`, `templates/`, `static/` |
| Компаньон и достижения | `arachne/companion.py` |
| Схема БД | `arachne/db.py`, константа `SCHEMA` |
| Сборка отчёта | `tools/make_report.py`, `tools/make_diagrams.py`, `tools/run_eval.py` |

### Инварианты — нарушать нельзя

1. **Геймификация не касается измерений.** Ни одна механика ниже не должна
   влиять на `arachne/evaluation/runner.evaluate()`, на страницу `/metrics`,
   на `tools/run_eval.py` и на сборку отчёта. Джокеры, проклятия, пьяный
   индекс, купленные стоп-слова — всё это живёт только в пользовательской
   выдаче `/search`. Метрики считаются по чистой конфигурации, всегда.
2. **Один рубильник.** `ARACHNE_COMPANION=0` в `.env` выключает всю
   геймификацию целиком (единственное исключение — механика №34, которая на
   этот флаг и реагирует). После выключения система выглядит как обычная
   лабораторная. Это режим для защиты.
3. **Схема БД идемпотентна.** Новые таблицы добавлять в `SCHEMA` через
   `CREATE TABLE IF NOT EXISTS`. Колонки в существующие таблицы не добавлять
   (`CREATE TABLE IF NOT EXISTS` не выполнит `ALTER`) — вместо этого заводить
   отдельную таблицу-спутник.
4. **Тесты зелёные.** `python -m pytest tests -q` — 36 тестов. На исправления
   F2 и F3 написать новые тесты, на экономику — отдельный файл
   `tests/test_economy.py`.
5. **Доступность не ломаем.** Escape закрывает любую модалку, клавиатурный
   скролл работает всегда, на тач-устройствах издевательства над скроллом
   отключаются. Иначе на защите это перестанет быть смешным.
6. Комментарии и строки интерфейса — по-русски, в тоне существующего кода.

## 1. Исправления (делать первыми)

### F1. Разметка: оценка ставится, но ничего не происходит

**Симптом.** На `/qrels` выбираешь оценку 2/1/0 — страницу выбрасывает наверх,
визуально ничего не меняется, метрики не двигаются.

**Что происходит на самом деле.** Оценка сохраняется корректно (проверено:
`qrels.rel` меняется, счётчик «оценено N, релевантных M» обновляется). Проблема
в обратной связи, и она тройная:

1. `app.py:721 judge()` отдаёт `RedirectResponse(f"/qrels?query_id={query_id}")`
   без якоря. Браузер встаёт в начало страницы, а таблица документов лежит под
   заголовком, лидом и двумя карточками.
2. Метрик на странице разметки нет вообще — они на `/metrics`, на другой
   вкладке.
3. Одна оценка двигает общий MAP примерно на 0,002. Замер: обнуление шести
   оценок у запроса №2 дало MAP 0,456 → 0,454, P@10 0,206 → 0,200. Даже если
   дойти до «Оценки качества», изменение не читается глазом.

**Что сделать.**

- В `templates/qrels.html` повесить `id="doc-{{ item.doc_id }}"` на `<tr>`
  строки пула; в `style.css` для этих строк `scroll-margin-top: 90px`.
- `judge()` → редирект на `/qrels?query_id={query_id}#doc-{doc_id}`.
- Поверх этого — отправка оценки через `fetch()` из `app.js` с обновлением
  класса строки и блока метрик без перезагрузки. Формы оставить рабочими без
  JS (progressive enhancement): `<form>` никуда не убирать, перехватывать
  `submit`.
- Новый блок на `/qrels` — **«Качество по этому запросу»**: P, R, F1, AP, nDCG,
  bpref для `current.id`, считаются через `arachne/evaluation/metrics.py`.
  Рядом с каждым числом — дельта к значению до последней оценки
  (`AP 0,62 → 0,71 <span class="delta-up">+0,09</span>`), с короткой анимацией.
  Предыдущее значение хранить в `settings` под ключом `qrels:last:{query_id}`.
- В блоке — строка «вклад в общий MAP: +0,002», чтобы было видно и то, и другое.

**Приёмка.** Ставлю оценку → страница остаётся на месте, строка перекрашивается,
AP запроса меняется на глазах.

### F2. Отметка релевантности + «все слова обязательны» = пустая выдача

**Симптом.** На `/search` с галкой «все слова запроса обязательны» запрос
«локальная сеть» даёт 21 документ. Достаточно нажать «Больше таких» у любого
документа — выдача становится **0 документов**. Насовсем, пока не сбросишь
отметки.

**Причина.** `search.py:77-81`: при активном `rocchio_vector` метод
`get_search_query_vector()` перезаписывает `self.query_lemmas` **всеми** леммами
вектора Рокчио (до 40 штук). Дальше `search.py:151` строит
`required = set(self.query_lemmas)`, и `search.py:173` требует, чтобы документ
содержал все 40 терминов. Этому условию удовлетворяет только сам отмеченный
документ, а после фильтров — вообще ничего.

**Что сделать.** Развести два понятия:

- `self.user_lemmas` — леммы, которые пользователь ввёл сам. Заполняются
  **всегда**, до ветки Рокчио, разбором `self.search_query`.
- `self.query_lemmas` — то, что реально лежит в векторе (после Рокчио и
  расширений). Используется для подсветки и объяснений.

`required` строить из `user_lemmas`. Ветку `if self.rocchio_vector:` перенести
после заполнения `user_lemmas` и `lemma_to_word`, чтобы они не терялись.

**Тест** (`tests/test_core.py`): запрос «локальная сеть», `all_words=True`, одна
положительная отметка → число результатов не меньше, чем без отметки.

### F3. «Слова запроса в документе» превращаются в мусор

**Симптом.** После любой отметки строка «Слова запроса в документе» вместо
четырёх слов показывает 74 случайные леммы: `звезда`, `коаксиальный`,
`кольцевой`, `выводить`…

**Причина.** Та же, что в F2: `search.py:194` строит чипсы по всем леммам из
`matched`, а после Рокчио там лежит весь вектор обратной связи. Плюс
`lemma_to_word` для этих лемм пуст, поэтому показываются сырые нормальные формы.

**Что сделать.** Чипсы строить только из `user_lemmas` и расширений (синонимы,
исправленные опечатки). Термины, пришедшие из Рокчио, выносить отдельной
свёрнутой строкой: «добавлено по вашим отметкам: …», серым, с пояснением, что
это метод Рокчио, а не слова запроса. Это ещё и наглядная демонстрация метода
для отчёта.

### F4. `/feedback` теряет контекст поиска

**Причина.** `app.py:345 post_feedback()` собирает редирект вручную из `q`,
`all_words`, `synonyms`. Фильтры по дате, номер страницы и флаг `use_feedback`
теряются: после отметки пользователь возвращается на первую страницу без своих
фильтров.

**Что сделать.** Добавить `date_from`, `date_to`, `page`, `use_feedback` в
скрытые поля формы в `results.html` и пробросить их в редирект. `q` пропускать
через `urllib.parse.quote`. Якорь — `#doc-{doc_id}`, как в F1.

## 2. Фундамент: экономика слов (№1)

> Добавлен сверх выбранного списка. Без него не работают механики №3, 4, 7, 10,
> 15, 17, 28, 36 — им всем нужен кошелёк, цена и место, где тратить.

### Суть

Валюта — не абстрактные очки, а **термины из индекса системы**. Цена термина
равна его информативности:

```
price(lemma) = round(100 * B_i) = round(100 * log(N / P_i))
```

где `N` — число документов в индексе, `P_i` — `terms.df`. «Сеть» стоит копейки,
«коаксиальный» — состояние. Кошелёк пользователя — это разреженный вектор, ровно
такой же объект, как вектор документа. Капитал = Σ `amount_i × price_i`,
показывается в шапке (`base.html`): «капитал: 1 240 сл.».

### Схема

```sql
CREATE TABLE IF NOT EXISTS wallet (
    lemma  TEXT PRIMARY KEY,
    amount INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS ledger (          -- история операций, для отладки баланса
    id     INTEGER PRIMARY KEY AUTOINCREMENT,
    ts     TEXT NOT NULL,
    reason TEXT NOT NULL,                     -- 'cashback', 'tax', 'purchase:fix-pagination', ...
    delta  INTEGER NOT NULL                   -- в «словах», не в леммах
);

CREATE TABLE IF NOT EXISTS purchases (        -- что куплено/разблокировано
    code      TEXT PRIMARY KEY,
    bought_at TEXT NOT NULL,
    meta      TEXT NOT NULL DEFAULT ''
);

CREATE TABLE IF NOT EXISTS pawned (           -- ломбард, механика №7
    code     TEXT PRIMARY KEY,                -- код достижения
    taken_at TEXT NOT NULL,
    due_at   TEXT NOT NULL,
    price    INTEGER NOT NULL
);
```

### Новый модуль `arachne/economy.py`

```python
price(conn, lemma) -> int                 # базовая цена по B_i
personal_price(conn, lemma) -> int        # с учётом личной инфляции (№3)
balance(conn) -> int                      # капитал в «словах»
earn(conn, amount, reason, lemma=None)    # начисление; без lemma — случайная редкая
spend(conn, amount, reason) -> bool       # списание; False, если не хватает
owns(conn, code) -> bool                  # куплено ли отключение
buy(conn, code, amount) -> bool
```

Списание всегда идёт с самых дешёвых позиций кошелька; если позиций не хватает,
`spend` возвращает `False` и Пафнутий комментирует. Стартовый капитал — 300 сл.
(три случайные средние леммы), выдаётся при первой индексации.

### Лавка `/shop`

Разделы: отключения издевательств, джокеры (№15), стоп-слова (№10), ломбард
(№7). Каждая позиция — код, цена, описание, кнопка. Купленное отражается в
`purchases` и проверяется через `economy.owns()`.

**Краны дохода** (иначе экономика мертва): кэшбэк за развёрнутые запросы (№4),
викторина (№13), блиц (№17), джекпот (№21). Если при балансировке окажется, что
слов не хватает — самый простой дополнительный кран — платить за разметку
релевантности (по 10 сл. за оценку), это заодно чинит мотивацию к скучной части
лабы.

### Флаги в `config.py`

```ini
ARACHNE_COMPANION=1     # общий рубильник геймификации (уже есть)
ARACHNE_ECONOMY=1       # кошелёк и лавка
ARACHNE_CRUELTY=1       # издевательства над UI (раздел 4)
ARACHNE_CURSE_CHANCE=0.07
```

## 3. Экономика

### №3. Личная инфляция

Чем чаще ты ищешь лемму, тем дешевле она для тебя стоит.

```
personal_price(lemma) = max(0.2, 0.97 ** k) * price(lemma)
```

`k` — сколько раз лемма встречалась в поле `query_log.normalized`. Пересчёт при
каждом поиске. На `/shop` — колонка «твоя цена» со стрелкой вниз и подписью
«‑34% из-за твоих запросов». Побочный эффект, который и делает механику игрой:
выгодно скупать то, что ты никогда не ищешь.

### №4. Налог на лень и кэшбэк за человеческий запрос

После каждого поиска, по `analysis` из `suggest.analyze()`:

| Условие | Эффект |
|---|---|
| значимых лемм ≤ 1 | налог 15 сл., реплика «одно слово — широкий улов, плати за широту» |
| лемм ≥ 4 и среди частей речи есть VERB / PRTF / INFN | кэшбэк `5 × число_лемм` |
| лемм ≥ 4 без глагола | кэшбэк `2 × число_лемм` |
| запрос повторяет предыдущий | ничего, реплика про дежавю |

Части речи уже приходят из `analysis.morphology[*].pos`. Механика прямо толкает
пользователя к естественно-языковым запросам — то есть к тому, что требует
вариант 3.

### №7. Ломбард Пафнутия

На `/shop/pawn`: заложить открытое достижение → получить 60% его оценки.
Оценка — фиксированная таблица в `companion.py` рядом с `ACHIEVEMENTS`
(от 200 сл. за «Первую паутину» до 900 за «Снайпера»). Срок выкупа — 7
календарных дней, выкуп за 100%. Просрочил — достижение уходит «в коллекцию
Пафнутия»: на `/achievements` показывается перечёркнутым, с подписью «у
Пафнутия, выкуплено им за долги» и датой. Вернуть можно только повторным
выполнением условия, и то за двойную цену.

### №10. Чёрный рынок стоп-слов

В лавке продаются `и`, `в`, `на`, `не`, `что` — по 500 сл., фиксированно.
Купленное стоп-слово действует **на один запрос**: если оно есть в тексте
запроса, оно не выбрасывается `morphology`, а входит в вектор с весом 3,0 и
сгорает. Эффект наглядный и абсурдный: наверх всплывают документы, где много
служебных слов, то есть просто длинные.

Реализация: `purchases` с кодом `stopword:и`, флаг читается в `search()` и
передаётся в `Search` как `allowed_stopwords: set[str]`. В блоке «Как система
поняла запрос» стоп-слово показывается с пометкой «куплено». **В
`runner.evaluate()` не применяется никогда.**

Пафнутий делает вид, что не при делах: «Я ничего не продавал. Вы ничего не
покупали».

## 4. Издевательства над интерфейсом

Все — под флагом `ARACHNE_CRUELTY`, все снимаются покупкой в лавке. Цены
подобраны так, чтобы отключить всё разом было дороже, чем заработать за вечер.

### №25. Ранжирование по настроению

Если за последние 15 запросов не открыт ни один документ, `mood = 'sulking'`:
выдача сортируется **по алфавиту заголовков** вместо косинуса. Внизу страницы,
шрифтом 0,7rem с `opacity: .5`: «ранжирование временно ведётся по алфавиту, см.
настроение Пафнутия». Лечится открытием любого документа из выдачи.

Счётчик открытий уже есть — `companion.bump(conn, "opened")`, нужен ещё счётчик
запросов с момента последнего открытия.

### №28. Пагинация-предатель

При переходе на страницу 2 с вероятностью 0,25 отдаётся страница 1 в
перемешанном порядке (seed от текущей минуты, чтобы обновление страницы давало
тот же результат и человек сомневался в себе). В подвале честно написано
«стр. 2». Покупка `fix-pagination` — 300 сл., снимает навсегда.

### №29. Паутина при бездействии

Чистый фронтенд в `app.js`. На `/search`: 12 секунд без клика, скролла и ввода —
от углов начинает расти SVG-паутина, `opacity` растёт до 0,75 за 40 секунд,
`pointer-events: none`, чтобы не блокировать клики. Клик по любому результату
рвёт её с анимацией и сбрасывает таймер. Покупка `no-cobweb` — 250 сл.

### №31. Инвертированный скролл на разметке

На `/qrels` колесо мыши инвертируется: `wheel` listener, `preventDefault()` +
`scrollBy(0, -delta)`.

**Важно:** не конфликтует с F1 и не заменяет его. F1 возвращает тебя на нужную
строку после оценки — это исправление реального дефекта. Инверсия — отдельная
шутка поверх работающей страницы. Снимается двумя путями: покупка
`normal-scroll` (250 сл.) **или** честный — разметить 20 документов, после чего
Пафнутий «признаёт тебя экспертом» и отключает сам.

Отключать на тач-устройствах и при `prefers-reduced-motion`. Клавиатурный скролл
(PgUp/PgDn/пробел) не трогать.

### №32. Модалка «Вы уверены?»

Перехватывает опасные действия: «Очистить базу», «Удалить документ из базы»,
«Сбросить отметки», «Загрузить эталон из CSV» (у первых двух сейчас обычный
`confirm()` в `templates/admin.html` и `document.html`).

Поведение: кнопки «Да» и «Нет» меняются местами через 1,2 с после открытия,
дальше каждые 0,8 с. При наведении на «Да» она один раз отпрыгивает. **Escape
закрывает модалку всегда** — иначе это не шутка, а ловушка, из которой нельзя
выйти. Покупка `honest-modals` — 400 сл.

### №36. Скидка за грубость

Короткий список в `data/rude_words.txt` (в `.gitignore` не нужен, но в отчёт не
включать). Если запрос содержит слово из списка:

- Пафнутий оскорбляется — отдельная группа реплик `offended` в `LINES`;
- выдаётся купон −10% на одну покупку (`purchases` с кодом `coupon`, `meta` =
  дата);
- не чаще одного раза в сутки.

Сами слова в интерфейсе не печатаются никогда — только реакция паука. Отдельная
ачивка `sorry` («Извинения приняты») за запрос «прости пафнутий».

## 5. Пафнутий

### №37. Тамагочи

Состояние в `settings`: `spider:hunger` (0–100), `spider:size` (0,8–1,6),
`spider:fed_at`.

| Событие | Сытость |
|---|---|
| новый документ в индексе после обхода | +3 за документ |
| переиндексация без новых документов | +1 |
| открытие документа из выдачи | +1 |
| оценка релевантности на `/qrels` | +2 |
| просто время | −5 в сутки |

**Внимание на баланс:** коллекция статична (108 документов), новые документы
появляются редко. Поэтому основной корм — активность пользователя, а новые
документы дают жирный разовый бонус. Иначе паук будет вечно голодным и механика
превратится в укор.

Поведение по уровню сытости: сытый (>70) иногда сам подсказывает синоним к
запросу; нормальный — обычные реплики; голодный (<30) ворчит и реже отвечает;
истощённый (<10, семь дней без еды) уходит, на его месте остаётся записка
«Ушёл искать мух. Вернусь, когда в индексе появится что-нибудь новое». Возврат —
после обхода сети.

Размер паука в `base.html` — через CSS-переменную `--spider-scale`.

### №41. Линька

Каждые 25 запросов — анимация линьки (паук на секунду сжимается, рядом падает
старый панцирь), выпадает случайная тема оформления:

| Код | Тема |
|---|---|
| `classic` | текущая |
| `web` | паутина, светлая |
| `night` | тёмная, готическая |
| `office` | канцелярия (та же, что в №34 — переиспользовать) |
| `terminal` | зелёный на чёрном |
| `notepad` | жёлтый блокнот в линейку |

Хранятся в `purchases` с префиксом `skin:`, выбор — в подвале. Дубль
конвертируется в 50 сл.

### №44. Патчноуты

При старте `run.py` и в разделе «Справка» — блок «Патч 1.0.N от Пафнутия», где
N — номер запуска (`settings: runs`). Текст генерируется из **реальных** значений
`config.py`: `ROCCHIO_BETA`, `ROCCHIO_GAMMA`, `EXPANDED_TERM_WEIGHT`,
`RESULTS_PER_PAGE`, `SNIPPET_LENGTH`, число документов и терминов.

Если значение изменилось с прошлого запуска (хранить снимок в `settings`) —
пишется честно: «ROCCHIO_BETA понерфлен с 0,75 до 0,70, жалобы в паутину».
Если ничего не менялось — шуточные строки про баланс из шаблонов в
`companion.py`. Побочная польза: сразу видно, что кто-то крутил конфиг между
прогонами метрик.

### №34. Заявление об отказе от паука

При `ARACHNE_COMPANION=0`:

- паук и тосты исчезают, ачивки продолжают писаться в БД молча;
- включается тема `office`: Times New Roman, серый, без иконок, все эмодзи
  заменены на `[—]`;
- в шапке появляется пункт «Заявление», страница `/disclaimer` — форма из трёх
  полей (ФИО, причина отказа, подпись) с подписью «заполняется в трёх
  экземплярах»; поля дублируются трижды на одной странице;
- отправка возвращает «Заявление принято к рассмотрению. Срок рассмотрения —
  30 календарных дней»; ачивка `paperwork` («Бюрократ») пишется в БД и
  всплывёт, когда паука вернут.

Поиск, ранжирование, разметка и метрики в этом режиме работают безупречно и без
единой шутки. **Это режим для защиты лабораторной.**

## 6. Игровые режимы

### №15. Джокеры (модификаторы запроса)

Перед поиском выпадают три случайных джокера из колоды. Один берётся бесплатно,
остальные — за слова. Действуют N запросов (по умолчанию 5), активные
показываются над выдачей.

| Код | Эффект | Точка врезки |
|---|---|---|
| `no-stop` | стоп-слова не выбрасываются | `text/morphology.py` |
| `sq-weights` | вес документа возводится в квадрат | скалярное произведение в `search.py` |
| `ban-node` | документы одного узла исключаются | фильтр по `documents.host` |
| `syn-x2` | вес расширений 0,5 → 1,0 | `config.EXPANDED_TERM_WEIGHT` |
| `idf-flat` | `B_i = 1` для всех, чистый TF | альтернативный вес в ранжировании |
| `short-doc` | бонус коротким документам | делить ранг на `log(term_count)` |

Все шесть — это параметры, которые `Search` уже умеет или почти умеет принимать.
Реализовать как поля датакласса `Search`, а не как правки внутри методов.

**Бонус для отчёта:** джокеры — это буквально конфигурации из раздела «сравнение
конфигураций». `metrics/compare` можно расширить теми же кодами и получить
готовую таблицу «влияние параметров модели на MAP» без дополнительной работы.
В метриках джокеры при этом **не активны по умолчанию** — только явным выбором
конфигурации на `/metrics/compare`.

### №13. Слепая выдача

Режим `/blind`. Система берёт случайный эталонный запрос из `eval_queries`,
показывает **четыре сниппета без заголовков, путей и узлов**, из которых ровно
один размечен как релевантный (`qrels.rel = 2`). Надо выбрать.

Подсказки:

| Подсказка | Цена | Реализация |
|---|---|---|
| 50/50 | 30 сл. | убрать два с `rel = 0` |
| Звонок Пафнутию | 60 сл. | LLM-слой, `ai/llm.py` |
| Помощь зала | 40 сл. | распределение по открытиям документов из `query_log` |

**Обязательный фолбэк:** `ARACHNE_LLM` по умолчанию выключен, поэтому «звонок
Пафнутию» при отсутствии LLM должен отвечать заготовкой, собранной из блока
«Почему найден» — назвать термин с наибольшим вкладом у правильного варианта.
Иначе механика мертва на любой машине без ключа.

Награда: 50 сл. за верный ответ, серия умножает на 1,2 (до ×3).

Побочная польза: режим полностью держится на эталонной разметке — чем больше
размечено, тем больше вопросов. Прямая мотивация к `/qrels`.

### №17. Блиц

Режим `/blitz`. Система берёт случайный документ и показывает **два предложения
из середины текста** (не первые 300 символов — иначе совпадёт со сниппетом).
Задача: найти этот документ поиском и кликнуть по нему в выдаче за 30 секунд.

Таймер съедает 2 сл. в секунду из капитала. Нашёл — 100 сл. и комбо ×1,2 за
каждый следующий подряд. Не нашёл — потерянное время не возвращается.

Проверка попадания: сравнить `document_id` кликнутого документа с загаданным.
Нужен обработчик клика по результату (уже есть переход на `/doc/{id}?q=`).

### №21. «Мне повезёт»

Кнопка рядом с «Искать» в `_searchform.html`. Открывает случайный документ из
индекса. Если он входит в top-10 выдачи по последнему запросу — джекпот 200 сл.,
реплика «Восемь глаз, и все везучие» и ачивка `lucky`. Иначе — «Не повезло.
Бывает». Бесплатно, раз в 10 минут.

### №18. Проклятый запрос

С вероятностью `ARACHNE_CURSE_CHANCE` (0,07) одна лемма запроса **молча**
заменяется синонимом из `data/synonyms_ru.json`. В блоке «Как система поняла
запрос» строка подменённого слова отличается только курсивом — заметить можно,
но надо смотреть.

Если пользователь нажал «Снять проклятие» (кнопка появляется в том же блоке,
всегда, независимо от наличия проклятия) — при наличии проклятия +80 сл. и
перезапуск поиска с чистым запросом; при отсутствии — −20 сл. за
подозрительность. Если ушёл со страницы, не заметив, — через 20 секунд Пафнутий
признаётся сам.

**Не применяется** на `/metrics`, `/qrels`, `/blind`, `/blitz`.

### №23. Пьяный индекс

Счётчик запросов подряд без паузы дольше 10 минут (`settings: streak`). После
20-го: в **сниппетах** (не в заголовках, не в тексте документа, не в исходном
файле) случайные соседние буквы меняются местами с вероятностью 0,04 на символ.
Пафнутий советует поспать. Сбрасывается паузой в 10 минут.

Реализация — постобработка в `text/snippets.py`, за флагом, который передаётся
из `app.py`. **Никогда** не включается в `runner.evaluate()`.

## 7. Разметка

### №47. Липовый эксперт

После сохранения оценки: если у запроса не меньше 8 оценок и **все** они `rel > 0`
(либо все равны 2) — поднять ачивку `fake-expert` («Липовый эксперт») и пометить
запрос подозрительным.

Таблица-спутник (колонку в `eval_queries` не добавлять, см. инвариант 3):

```sql
CREATE TABLE IF NOT EXISTS qrels_suspect (
    query_id  INTEGER PRIMARY KEY REFERENCES eval_queries(id) ON DELETE CASCADE,
    marked_at TEXT NOT NULL
);
```

На `/metrics` такие запросы подсвечиваются в таблице «Метрики по каждому
запросу», а под таблицей — строка: «N запросов помечены как подозрительные:
разметка без единого нерелевантного документа завышает точность и вырождает
bpref». Метка снимается автоматически, как только у запроса появляется хотя бы
одна оценка 0.

Это не только шутка: перекос разметки — реальная проблема эталона, и в отчёт
это можно вписать как валидацию качества разметки. Формулировка про bpref уже
есть в `templates/qrels.html`, она согласуется.

## 9. Чего не делать

- Не трогать формулы (1.5) и (1.6), косинусную меру и метод Рокчио как таковые —
  это защищаемое ядро варианта 3.
- Не добавлять внешних зависимостей во фронтенд. Ванильный JS, инлайновый SVG.
- Не хранить игровое состояние в `localStorage` — только в SQLite, иначе оно
  потеряется и отладить баланс будет невозможно.
- Не вставлять геймификацию в `tools/make_report.py` — отчёт по лабораторной
  собирается из чистых данных.
- Не делать ни одну механику необратимой без возможности выключения: у каждого
  издевательства есть цена отключения, у всей надстройки — флаг `.env`.

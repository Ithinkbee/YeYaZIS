С чего начать

  1. Откройте раздел Индекс.
  2. Добавьте ресурс локальной сети: обычный каталог (D:\Отдел) или сетевую папку (\\сервер\обмен). Для знакомства с системой есть кнопка «Добавить тестовые узлы ЛВС».
  3. Нажмите «Запустить обход и индексацию». Паук обойдёт каталоги, извлечёт текст из файлов txt, md, html, docx, pdf, rtf и построит индекс.
  4. Вернитесь на страницу Поиск и задайте вопрос обычными словами.

Повторный обход разбирает только изменившиеся файлы, поэтому его можно запускать регулярно — например, после пополнения общей папки.

Как формулировать запрос

  • Пишите обычным языком: «настройка локальной сети», «как работает коммутатор». Система сама приведёт слова к нормальной форме, поэтому «сетей», «сети» и «сеть» — одно и то же слово.
  • Служебные слова (предлоги, союзы, местоимения) отбрасываются — они есть почти в каждом документе и не помогают различать их.
  • Чем больше содержательных слов, тем точнее выдача, но тем выше риск, что часть документов отсеется. Начните с двух-трёх ключевых слов.
  • Флажок «все слова запроса обязательны» оставляет только документы, где встретились все слова. Это повышает точность и снижает полноту.
  • Фильтр по дате ограничивает выдачу документами, добавленными в базу в указанном промежутке.

Как работает поиск

Система использует векторную модель. Каждый документ представлен вектором весов терминов, вес вычисляется по формулам:

Bi = log( N / Pi )   — инверсная частота термина;
Aij = Qij · Bi   — вес термина i в документе j,

где N — число документов в базе, Pi — число документов с термином i, Qij — частота термина в документе. Термин, встречающийся почти везде, получает вес около нуля; редкий термин, наоборот, сильно влияет на ранжирование.

Запрос превращается в вектор той же размерности: вес слова равен единице, если слово в запросе есть, и нулю иначе. Релевантность — косинус угла между векторами:

sim(D, Q) = (D, Q) / ( ‖D‖ · ‖Q‖ )

Документы выдаются в порядке убывания этой величины. У каждого результата можно раскрыть блок «Почему найден» — там показан вклад каждого термина в итоговый ранг.

Подсказки системы

  • Автодополнение. При наборе система предлагает продолжения из словаря индекса и ранее заданных запросов.
  • Исправление опечаток. Если слова нет в словаре, подбирается ближайшее по редакционному расстоянию — появляется подсказка «Возможно, вы имели в виду».
  • Разбор запроса. Блок «Как система поняла запрос» показывает нормальные формы, части речи и отброшенные стоп-слова.
  • Синонимы. Запрос дополняется терминами из тезауруса (например, «коммутатор» ↔ «свитч») с пониженным весом.
  • Обратная связь. Кнопки «Больше таких» и «Не то» перестраивают вектор запроса методом Рокчио, и выдача уточняется под вашу задачу.
  • Похожие документы. На странице документа — список ближайших по косинусной мере.

Оценка качества

Раздел Оценка качества сравнивает выдачу системы с эталонной разметкой из раздела Разметка.

МетрикаЧто показывает
Точность (P)доля релевантных среди выданных документов
Полнота (R)доля найденных релевантных среди всех релевантных
F-мерагармоническое среднее точности и полноты
P@nточность в пределах первых n документов выдачи
R-точностьточность на уровне R, где R — число релевантных
AP, MAPсредняя точность по запросу и по набору запросов
nDCGучитывает, что документ выше в списке ценнее

График «точность — полнота» строится по одиннадцати уровням полноты с интерполяцией: Pint(r) = max{ P(r′) : r′ ≥ r }.

Если что-то не так

  • Ничего не найдено. Проверьте подсказку об опечатке, отключите режим «все слова обязательны», снимите фильтр по дате, оставьте одно-два слова.
  • Документ есть в папке, но не находится. Убедитесь, что его расширение поддерживается и что после добавления файла выполнен обход.
  • Файл не открывается по ссылке. Возможно, он перемещён или нет прав доступа к сетевому ресурсу — запустите обход, чтобы обновить базу.
  • Выдача «замусорена». Отметьте неудачные результаты кнопкой «Не то» — система перестроит вектор запроса.
